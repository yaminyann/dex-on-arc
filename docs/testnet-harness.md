# Testnet harness

Arc Testnet has no Chainlink Data Feeds and no 0x support, so by default nothing priced by an oracle can be traded there. To let you try every order type end to end on real contracts and real transactions, the project includes a **testnet-only harness**. It is clearly labelled in the UI (a TEST badge on every harness token and a banner on the network) and it must never be deployed to mainnet.

## What it adds

| Piece | Contract | What it is |
| --- | --- | --- |
| Test assets | `contracts/testnet/TestToken.sol` | Mintable ERC-20s: **tBTC** (8 decimals), **tETH** (18) and **tSOL** (9). Each has a public `faucet()` that gives a fixed amount and stops at ten times that amount per wallet. They have no value. |
| Test price feeds | `contracts/testnet/TestPriceFeed.sol` | A Chainlink-shaped feed (8 decimals) whose price **anyone** can set. Seeded from the current Coinbase Exchange price at deploy time. This is what lets you trigger a stop, limit or trailing order on demand. |
| Test router | `contracts/testnet/TestSwapRouter.sol` | Stands in for the aggregator. `swapExactIn` pulls the input with `transferFrom` from the caller (the same shape as the real AllowanceHolder flow) and pays the output at the feed price minus a fixed 0.10% fee. Test tokens are minted on demand; USDC is paid from the router's own balance. |
| A USDC feed | `TestPriceFeed` | The order contract also prices the quote token (USDC) from a feed, so a test USDC/USD feed fixed at 1.00 is registered. |
| A fresh order contract | `contracts/ArcTradeOrders.sol` | The same audited production source, deployed with the harness deployer as owner so that it can register the test feeds and the router. |

The real testnet tokens (EURC, cirBTC, WETH) stay in the token list but have no feed, so the UI says they cannot be traded.

## What it proves, and what it does not

It proves that the production order contract, the keeper, the frontend and the transaction flows work together on a live chain: escrow, trigger evaluation, keeper execution through an allowlisted target, exact-spend and net-output checks, the keeper fee, refunds, expiry and DCA scheduling.

It does **not** prove anything about real market prices, real liquidity, real aggregator calldata or real Chainlink feeds. Prices here are set by whoever called `setPrice` last. Slippage and depth behave like a fixed-fee router, not like a DEX.

## The timelock applies to the harness too

The order contract enforces a minimum configuration delay of one hour, and the harness does not bypass it. Deploying queues the feed and router registrations; they become usable only after `applyConfig` is called once the delay has passed. Until then the UI shows "No oracle feed" for the test tokens. Apply them with:

```bash
bun run server/testnet/apply-config.ts
```

The script is idempotent: it prints the seconds remaining for entries that are not ready and skips entries that are already applied.

## Scripts

| Script | Purpose |
| --- | --- |
| `server/testnet/deploy-harness.ts` | Deploys the order contract, router, feeds and tokens; queues the configuration; seeds the router with USDC; writes `src/trading/testnet-harness.json`. Needs `TESTNET_DEPLOYER_PRIVATE_KEY`. |
| `server/testnet/apply-config.ts` | Applies the queued configuration after the delay. |
| `server/testnet/e2e.ts` | Live end-to-end test (see below). |

`TESTNET_DEPLOYER_PRIVATE_KEY` is a throwaway Arc Testnet key kept in `.env`. It holds testnet USDC only (USDC is the gas token on Arc). Never reuse a key that has ever held real funds, and never put one in a `VITE_` variable.

## Using it in the app

1. Select Arc Testnet and pick **tBTC**, **tETH** or **tSOL** (marked TEST).
2. In **Testnet tools**: get test tokens from the faucet, read the current test price, and set a new price (or step it by -10%, -5%, +5%, +10%). **Refresh feed** re-stamps the price so it does not go stale (feeds are registered with the longest allowed staleness, two days).
3. Market orders go to the test router (route shown as "Test router"). Conditional orders and DCA go to the order contract.
4. Start a keeper so triggered orders actually run:

```bash
KEEPER_ENABLED=true KEEPER_PRIVATE_KEY=$TESTNET_DEPLOYER_PRIVATE_KEY bun run server
```

On testnet the keeper fills swaps through the quote gateway, which serves the test routers as providers (`test-router`, `test-router-b`). Limit them with `GATEWAY_PROVIDERS`.

## Second router (rehearsing an extra aggregator)

`server/testnet/deploy-router-b.ts` deploys a second `TestSwapRouter`, queues it as a swap target on the order contract and funds it. After the config delay, `apply-config.ts` allowlists it. This is the testnet rehearsal of what mainnet needs for every additional aggregator router (KyberSwap, 0x): an onchain, timelocked allowlist entry that keepers can then use. Router B pays outputs from its own balance (the test tokens have a single minter, router A), so keep test sizes small.

## Router liquidity

Buying a test token mints it, so that side has no limit. Selling a test token pays **USDC from the router's balance**. The harness seeds the router with the deployer's spare testnet USDC at deploy time; keep sell sizes small (a few USDC) and top the router up by sending it USDC if sells start failing with `InsufficientLiquidity`. The Testnet tools panel shows the router's USDC balance and warns when it is low.

## Live end-to-end test

`server/testnet/e2e.ts` creates a throwaway trader wallet, funds its gas from the deployer, and then runs these scenarios against the live deployment, with a keeper submitting the executions:

| Scenario | What it asserts |
| --- | --- |
| Oracle reads | The order contract's price for each test token matches its feed. |
| Limit sell | Not executable before the trigger; fills through the keeper after the price rises; the trader receives about the expected USDC. |
| Stop-loss | Fills after a drop through the trigger. |
| Take-profit | Fills after a rise through the trigger. |
| Trailing stop | The keeper records the new peak; a reversal larger than the trail fills it. |
| OCO | The take-profit leg fires once; the order then reports "not open". |
| Stop-limit | Activation persists; no fill below the limit price; fills after a rebound inside the limit. |
| Cancel | Escrow is taken and fully refunded. |
| Expiry | A keeper refunds an expired order. |
| DCA | The first buy runs on schedule; pause, resume and cancel work; the remaining budget is refunded. |
| Market swap | A swap through the test router (the transaction the UI sends) delivers tokens. |

Run it with a keeper running:

```bash
bun run server/testnet/apply-config.ts
KEEPER_ENABLED=true KEEPER_INTERVAL_MS=3000 KEEPER_PRIVATE_KEY=$TESTNET_DEPLOYER_PRIVATE_KEY bun run server &
bun run server/testnet/e2e.ts
```

Results are printed per scenario and written to `/tmp/e2e-results.json`.

## Removing it

Delete `contracts/testnet/`, `server/testnet/`, `src/trading/testnet-harness.json`, the harness imports in `src/trading/networks.ts`, `src/trading/aggregator.ts`, `server/keeper.ts`, and `src/components/TestnetTools.tsx`. Mainnet is unaffected: it never references the harness.
